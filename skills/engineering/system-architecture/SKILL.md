# System Architecture

## Use this skill when

New systems, major features, architectural decisions, or structural redesigns.

## Workflow

1. Map entry points, modules, data flow, dependencies, persistence, and integrations.
2. Clarify functional and non-functional needs, constraints, and compatibility commitments.
3. Prefer the simplest architecture that meets needs; define boundaries around independent responsibilities.
4. Document decisions, trade-offs, failure modes, and migration implications.
5. Plan incremental adoption and rollback or compatibility strategy.

## Verification

Validate against use cases, dependency direction, testability, operations, and migration risks.

## Boundaries

Do not introduce microservices, queues, or abstractions without a concrete requirement.
